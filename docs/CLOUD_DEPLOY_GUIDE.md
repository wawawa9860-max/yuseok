# 클라우드 배포 가이드 — 클릭만으로 운영 서버 만들기

> 대상: 본사 담당자 (개발 지식 불필요).
> 결과: `https://○○○.up.railway.app` 같은 **운영 주소가 자동으로 생깁니다.**
> 도메인을 따로 사거나 서버 컴퓨터를 둘 필요가 없습니다.
> 걸리는 시간: 처음 한 번, 약 15분.

## 왜 Railway 인가

- 서버 + 데이터베이스 + **https 주소**를 한 화면에서 클릭으로 만듭니다.
- 이 저장소에 배포 설정(`Dockerfile`, `railway.json`)이 이미 들어 있어서
  **저장소를 연결하면 알아서 빌드되고, 켜지면 DB 구조와 본사 계정까지 자동으로 만들어집니다.**
- 비용: 월 $5 (Hobby 요금제) 수준. 현장 1~2곳 Pilot 에 충분합니다.

> 딱 하나, **가입만은 본인이 직접 해야 합니다.** (결제 수단 등록이 필요하기 때문입니다.)
> 그 다음부터는 아래 순서대로 클릭만 하면 됩니다.

---

## 1. 가입 (1회)

1. https://railway.app 접속 → **Login** → **GitHub 계정으로 로그인**
   (이 저장소가 있는 GitHub 계정 그대로)
2. 요금제는 **Hobby** 를 선택합니다.

## 2. 프로젝트 만들기 + 저장소 연결

1. **New Project** → **Deploy from GitHub repo** → `wawawa9860-max/yuseok` 선택
2. 처음이면 "Configure GitHub App" 이 뜹니다 → 이 저장소에 접근 허용
3. 배포가 자동으로 시작됩니다 (첫 빌드는 몇 분 걸립니다 — 이때는 아직 안 켜지는 게 정상입니다.
   아래 환경값을 넣어야 켜집니다)

## 3. 데이터베이스 붙이기

1. 프로젝트 화면에서 **+ Create** (또는 New) → **Database** → **Add PostgreSQL**
2. 끝. (접속 정보는 다음 단계에서 자동으로 끌어다 씁니다)

## 4. 환경값 4개 넣기

앱 서비스(yuseok) 클릭 → **Variables** 탭 → 아래 4개를 추가합니다.

| 이름 | 값 | 설명 |
|---|---|---|
| `ADMIN_DATABASE_URL` | `${{Postgres.DATABASE_URL}}` | **이 글자 그대로** 붙여넣으면 Railway 가 3번의 DB 주소로 바꿔 줍니다 |
| `APP_DB_PASSWORD` | 직접 정한 강한 비밀번호 | 예: `hyundae-rfcip-2026-secure!` — 서버 내부용이라 외울 필요 없습니다 |
| `JWT_SECRET` | 아무 문장이나 **32자 이상** | 예: 한글 자판 그대로 길게 두드린 문자열도 됩니다. 로그인 보안용입니다 |
| `INITIAL_ADMIN_PASSWORD` | 본사 로그인 비밀번호 (8자 이상) | **이건 외우십시오.** 첫 로그인에 씁니다 |

> `PUBLIC_BASE_URL`(카카오톡 링크 주소)은 넣지 않아도 됩니다 —
> Railway 가 주는 도메인을 서버가 자동으로 사용합니다.
> DB 이름·계정·주소 조립도 전부 자동입니다.

## 5. 주소(도메인) 만들기

1. 앱 서비스 → **Settings** 탭 → **Networking** → **Generate Domain**
2. `https://yuseok-production-○○○.up.railway.app` 같은 주소가 생깁니다.
   **이게 운영 주소입니다.** 현장관리자에게 카카오톡으로 보낼 주소이기도 합니다.

## 6. 사진·영수증 저장공간 붙이기 (중요)

Railway 는 재배포 때 서버 안의 파일이 지워집니다. 영수증 사진을 지키려면:

1. 앱 서비스에서 마우스 오른쪽 클릭 (또는 Settings) → **Attach Volume**
2. Mount path 에 `/app/storage` 입력 → 추가

## 7. 확인

1. 배포 상태가 초록색(Active)이 되면 5번에서 만든 주소를 엽니다.
2. 로그인 화면이 나오면: 아이디 `admin`, 비밀번호는 4번의 `INITIAL_ADMIN_PASSWORD`.
3. 본사 대시보드 → **[계정 관리]** → 현장관리자 계정을 만듭니다.
   **여기서부터는 전부 웹 화면입니다. 파일이나 명령어를 만질 일이 없습니다.**

첫 화면이 안 뜨면: 앱 서비스 → **Deployments** → 최근 배포 → **View Logs**.
빠진 값이 있으면 서버가 **한국어로** 무엇이 빠졌는지 말해 줍니다.

## 이후 운영

| 하고 싶은 것 | 하는 곳 |
|---|---|
| 계정 만들기·비밀번호 재설정·중지 | 웹 → 본사 대시보드 → 계정 관리 |
| 현장 등록, 사전 업로드 5종, 일일 운영 | 전부 웹 (docs/PILOT_GUIDE.md 5단계부터) |
| 프로그램 업데이트 | GitHub 저장소에 새 코드가 올라오면 Railway 가 **자동 재배포** |
| DB 구조 변경 | 재배포 때 서버가 **자동 적용** (마이그레이션 자동 실행) |

### 나만의 도메인을 쓰고 싶다면 (선택)

`rfcip.회사이름.com` 같은 주소를 원하면 도메인 구입 후
Railway → Settings → Networking → **Custom Domain** 에 연결하면 됩니다.
Pilot 단계에서는 자동 발급 주소로 충분합니다.

### 다른 방법과의 비교

| 방법 | 장점 | 단점 |
|---|---|---|
| **Railway (권장)** | 클릭 몇 번, 자동 도메인, DB 포함 | 월 $5 |
| 사무실 PC | 무료 | PC 를 항상 켜둬야 하고, 외부(현장 휴대폰)에서 접속하려면 네트워크 설정이 복잡함 |
| Render 등 다른 클라우드 | 비슷하게 동작 (서버가 Render 도메인도 자동 인식) | DB 무료판이 90일 만료 등 제약 |
