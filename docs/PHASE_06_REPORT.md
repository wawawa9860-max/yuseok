## 0. 비전문가용 한 줄 요약

**드디어 화면이 나왔습니다.** 그리고 이 프로젝트가 애초에 노린 것이 실제로 되는지 처음 확인했습니다.

> "50~60대 현장관리자가 휴대폰으로 하루 약 1~3분 내에 입력을 완료" (§0)

실제 휴대폰 크기 브라우저에서 처음부터 끝까지 눌러본 결과입니다.

```
[오늘 작업 입력]  →  종료번호 누르기  →  [예]  →  [없음]  →  [입력완료]

  터치 5번.  타이핑 0번.
```

시작번호는 "다음에 뚫을 번호"로 **이미 채워져 있어서** 종료번호만 누르면 됩니다.
지층별 수량(토사 182m, 풍화암 78m)과 공정률(21.7%)은 **현장관리자가 손대지 않아도** 자동으로 계산됩니다.

## 1. 이번에 구현한 기능

### 1.1 산출근거 기준 판단 (요청사항)

| 항목 | 판단 | 근거 |
|---|---|---|
| H-Pile 규격 | **`H-300x300*10*15` (94 kg/m)** | 산출근거의 중량계산이 이 규격 기준 (`1,080 × 94 = 101.52 ton`). 내역서는 규격 표기만 갱신 누락 |
| 공수 | **108공 (무근 54공, `16-1` 포함)** | 산출근거 콘크리트 `2,052m = 1,080 + 972`, `972 ÷ 18 = 54공` |
| `16-1` | **도면 누락으로 판단** | §11 우선순위: 계약 수량산출서 > 승인 도면 |

시스템은 이 판단과 이미 같게 동작합니다 — `16-1` 을 삭제하지 않고 `확인필요` 로 보존합니다.

### 1.2 §18 통합 메인화면

ERP 사이드메뉴 없이 화면 하나입니다.

```
○○현장 RF CIP
8월 27일 (목)

  오늘 13공   누계 13공   공정률 21.7%

[ 오늘 작업 입력 ]        ← 파란 큰 버튼
[ 천공현황 / 도면 · 준비중 ]
[ 비용 · 증빙 · 준비중 ]
[ 특이사항 · 준비중 ]
[ 오늘 보고서 · 준비중 ]
[ 카카오톡 공유 · 준비중 ]
```

다음 Phase 기능은 자리를 잡아두고 `준비중` 으로 비활성 표시했습니다.
현장관리자가 "이 앱이 뭘 하는지" 한눈에 알 수 있어야 하기 때문입니다.

### 1.3 §19 천공번호 고르기 — 타이핑하지 않는다

천공번호를 손으로 입력하면 오타가 나고 시간이 걸립니다.
**미시공 번호를 버튼으로 늘어놓고 눌러서** 고릅니다.

```
시작  A-001        종료  A-013      ← 시작은 미리 채워져 있다
┌───────┬───────┬───────┐
│ A-001 │ A-002 │ A-003 │           선택: 진한 파랑
│ A-004 │ A-005 │ A-006 │           범위 안: 연한 파랑
│  ...  │       │       │
└───────┴───────┴───────┘
```

### 1.4 §20 지층별 자동집계

범위를 고르는 즉시 계산됩니다. **현장관리자는 지층 수량을 한 번도 입력하지 않습니다.**

```
오늘 13공 · 260 m
  토사      182 m
  풍화암     78 m
  누계       13공
  잔여       47공
  공정률   21.7 %
```

### 1.5 §16 실제심도 — 같으면 묻지 않는다

```
계획심도와 동일합니까?     [ 예 ]  [ 아니오 ]
```

`예` 하나로 13공의 실제심도가 계획심도로 채워집니다.
`아니오` 를 골랐을 때만 번호별 입력칸이 나오고, **비워둔 공은 계획심도를 그대로 씁니다.**

### 1.6 §15 지반조건 특이사항 — 있을 때만 남긴다

```
계획 지반조건과 다른 점이 있었습니까?     [ 없음 ]  [ 있음 ]
```

`없음` 이면 **아무것도 저장되지 않습니다.** `있음` 을 고르면 선택지가 나오는데,
이 선택지는 **현장에 등록된 지층종류에서 만들어집니다** — 하드코딩이 아닙니다.

```
토사구간 차이 / 풍화암구간 차이 / 연암구간 차이 / 예상 외 지층 / 지하수 / 기타
```

미확정(`PROVISIONAL`) 지층인 연암도 선택지에 있어, 실제로 나오면 바로 기록됩니다.

## 5. 계산 규칙

전부 결정론적입니다 (§46).

| 항목 | 규칙 |
|---|---|
| 금일 공수 | 범위 내 천공번호 중 **미완료인 것만** |
| 금일 천공연장 | `Σ design_depth_total` |
| 지층별 수량 | `Σ ground_profile_layer.planned_length` (§20) |
| 실제심도 | `depth_same_as_plan` → `design_depth_total`, 아니면 입력값 (§16) |
| 물량 공정률 | `누적 완료 계약수량 / 전체 계약수량 × 100` (§36) |
| 누계·잔여 | 현재 실적 + 오늘 선택분 |

### 공정률 기준을 숨기지 않습니다

`fn_site_progress` 는 `quantity_basis` 를 함께 돌려줍니다.

```
CONTRACT_QUANTITY  계약수량 기준 (§36 정상)
DESIGN_DEPTH       계약수량 미연결 → 계획심도로 대신 계산
NONE               둘 다 없음
```

계약수량이 연결되지 않은 현장에서 공정률이 **영원히 0% 로 보이는 함정**을 이번에 발견해
막았습니다. 자동검증도 `NO_CONTRACT_QUANTITY` / `PARTIAL_CONTRACT_QUANTITY` 로 본사에 알립니다.

### 실제 브라우저에서 확인한 것

테스트만으로는 "화면이 실제로 되는가" 를 알 수 없어, **휴대폰 크기(390×844) 브라우저**에서

```

집계:      토사 182m / 풍화암 78m / 누계 13공 / 잔여 47공 / 공정률 21.7%
```

### 이번에 잡은 버그 3건 — 전부 브라우저에서 나왔다

**① 앱이 존재하지 않는 API 를 불렀다**
`/api/field/sites/:id/holes` 를 호출했는데 실제 경로는 `/api/sites/:id/holes` 였습니다.
**API 테스트는 올바른 경로를 직접 불러서 이 버그를 못 잡았습니다.**
화면을 실제로 띄워보지 않았다면 현장에서 처음 발견됐을 것입니다.

**② 범위 선택이 두 번째 터치에서 초기화됐다**
시작번호가 미리 채워져 있는데, 첫 탭이 종료로 들어가고 두 번째 탭이 범위를 지웠습니다.
규칙을 `web/pick.js` 로 분리하고 **회귀 테스트 6건**으로 고정했습니다.

```
★ 미리 채워진 시작번호를 눌러도 초기화되지 않는다
```

**③ 공정률이 항상 0% 로 나왔다**
계약수량이 연결되지 않은 현장에서 분모가 0 이라 공정률이 영원히 0% 였습니다.
계획심도로 대신 계산하되 **어떤 기준을 썼는지 함께 돌려주도록** 고쳤습니다.

## 8. 사람이 직접 확인해야 할 사항

> ★ 이번 Phase 의 확인은 **실제 현장관리자가 직접 써보는 것**입니다.

1. **실제 현장관리자 1명에게 설명 없이 써보게 하십시오.** §52 성공기준은
   "50~60대 사용자가 별도 설명 없이 기본입력 가능" 입니다.
   제가 확인한 것은 터치 횟수와 화면 크기이지, **실제 사용자의 이해도가 아닙니다.**

2. **글씨 크기 19px 가 충분합니까?** 화면에서 직접 보시고 더 키울지 알려주십시오.

3. **번호 버튼 방식이 맞습니까?** 공수가 수백 개인 현장에서는 목록이 길어집니다.
   구간별로 접거나, 숫자 키패드를 함께 두는 방안을 검토할 수 있습니다.

4. **하루에 두 구간을 따로 뚫는 경우**가 있습니까? 현재는 한 번에 한 범위만 고릅니다.
   (제외번호로 처리하거나, 저장을 두 번 하면 됩니다)

5. 내역서 H-Pile 규격을 `H-300x300*10*15` 로 수정 (1.1 판단 반영)

6. 조서 합계행 `A61` 공수 29 → 54 (아직 미수정)
