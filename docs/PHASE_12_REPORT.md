## 0. 비전문가용 한 줄 요약

**본사가 전 현장을 한 화면에서 봅니다. 이상한 현장에만 표시가 붙습니다.**

§39 가 정한 그대로입니다.

> "현장별 한 줄 위주의 단순 화면으로 설계한다.
>  본사 담당자가 이상현장만 클릭해 상세정보를 확인하도록 한다."

한 줄에는 §39 항목이 다 들어갑니다 — **현장명 · 금일 공수 · 누계 공수 · 공정률 ·
레미콘 · 비용증빙 상태 · 기성 · 특이사항.**

이상현장은 시스템이 먼저 표시합니다. 검토필요 특이사항 / 증빙대기 / 레미콘 지연 /
금일 입력 없음 / 검증 ERROR — 이 표시가 붙은 카드만 누르면 됩니다.

**원가 합계는 이 단계에서 처음으로 화면에 나옵니다.** 그래서 상세 화면에만 두었고,
API 와 DB 함수 양쪽에서 본사 외에는 막았습니다 (§29 3중 방어 그대로).

먼저, 지난 확인사항 세 가지도 반영했습니다.

| 확인사항 | 반영 |
|---|---|
| 특이사항 유형 | **확정 8종으로 교체** — 소음 민원발생 / 진동 민원발생 / 레미콘 수급 지연 / 가설휀스 간섭 / 작업부지 미조성 / 검측지연 / 지반조건 상이 / 기타(입력) |
| 음성메모 | **제거** — 사진·PDF 만 받습니다. 음성 파일을 보내면 거부합니다 |
| 종결권한 | **본사만** — 이미 그렇게 되어 있어 테스트로 재확인만 했습니다 |

**기타는 입력입니다.** 내용 없이 '기타' 만 저장하려 하면 화면과 서버와 DB 세 곳에서 막습니다.

## 1. 이번에 구현한 기능

### 1.1 §39 현장별 한 줄

```
시험현장 RF CIP                              20%
금일 12공 · 4공수 · 레미콘 68㎥          12/60공
증빙 0/1 · 특이사항 1건
[검토필요 특이사항] [증빙대기 1건] [레미콘 지연]   ← 이상표시
```

이상표시가 붙은 카드는 왼쪽에 주황 띠가 생깁니다. 본사는 그것만 누릅니다.

이상 판정 5종: **검토필요 특이사항 · 증빙대기 N건 · 레미콘 지연 · 금일 입력 없음
(입력을 시작한 현장만) · 검증 ERROR.**

### 1.2 이상현장 클릭 → 상세

물량·금액 공정률, 검증 결과(ERROR/WARN/INFO), 특이사항 목록과 함께
**이번달 투입원가 합계**가 나옵니다.

```
이번달 투입원가 (본사 전용)     420,000원
  유류비 (1건)                 420,000원
  시공 인정금액 대비             3.5%     ← 손익을 가늠하는 한 줄
이 칸은 본사에게만 보입니다 (§29).
```

### 1.3 본사 로그인 = 대시보드

`head01` 로 앱에 로그인하면 현장 화면이 아니라 **대시보드가 바로** 열립니다.
같은 주소, 같은 앱, 권한으로만 갈립니다.

## 4. 화면 변경사항

- 본사 계정 로그인 → **대시보드** (현장별 카드, 이상표시, 클릭 → 상세)

## 8. 사람이 직접 확인해야 할 사항

1. **이상 판정 5종이 적절합니까?** 기준(예: 증빙대기 몇 건부터)을 바꿀 수 있습니다.
2. **원가 상세의 '시공 인정금액 대비'** — 손익 가늠용 한 줄로 넣었습니다.
   노무·장비 자동계산이 아직 단가 미등록이라 수동입력 비용만 잡힙니다.
   실제 단가가 들어오면 이 비율이 의미를 갖습니다.
3. 이월된 미결: 실제 단가·지급방식, 월 기준일수, 계획 레미콘량 표기,
   내역서 H-Pile 규격, 작업일보 확정 스냅샷, **R20 실사용 시험**.

## 9. 발견된 위험

- **'금일 입력 없음' 표시는 입력을 한 번이라도 시작한 현장에만** 붙습니다.
  설정 중인 현장까지 이상으로 표시하면 표시가 늘 붙어 있어 의미가 없어집니다.
- 대시보드는 실시간 집계라 현장이 많아지면 느려질 수 있습니다.
  Pilot(1현장)에는 문제없고, 필요해지면 캐시를 붙입니다.
