## 0. 비전문가용 한 줄 요약

Master Prompt는 이렇게 못박습니다.

> "현장에서 수백 개 천공번호를 하나씩 입력하게 해서는 안 된다. 반드시 범위 지정 기능을 만든다." (§10)

이번 단계가 그것을 만든 단계입니다. **`A-031 ~ A-065` 처럼 범위만 찍으면 35공에 지반조건이 한 번에 들어갑니다.**

그리고 수량산출서가 주는 형태가 세 가지로 다르기 때문에, **세 가지 입력경로를 모두** 만들었습니다.

| 수량산출서가 주는 형태 | 입력경로 |
|---|---|
| "A-031~A-065 구간은 토사 10m, 풍화암 7m, 연암 4m" | **범위 일괄적용** |
| "A-001~A-030 토사 합계 360m, 풍화암 합계 240m" | **총연장 → 공당 환산** |
| 공마다 값이 제각각 (실제 천공조서가 이 형태) | **공별 원본값 적용** |

세 경로 모두 **저장 전에 미리보기가 먼저 나옵니다.** 몇 공이 대상인지, 합계가 맞는지,
기존 값을 덮어쓰게 되는지를 보여주고 확인을 받은 뒤에야 저장합니다.

## 1. 이번에 구현한 기능

### 1.1 지시사항 반영

| 지시 | 반영 결과 |
|---|---|
| 무근 표기를 `1-1, 1-2, 1-3` 형식으로 | 시드 재추출 완료. 29공이 `1-1…1-10, 2-1…2-10, 3-1…3-9` 로 정리되고 H-PILE `1~29` 와 충돌 없음 |
| 연암·경암은 현장 여건 미확정이라 0으로 입력해 둠 | **지워버리지 않고 `PROVISIONAL`(미확정) 상태로 보존.** 실제 출현 시 즉시 계획에 편입 가능 |
| 638.30공이 정답, 조서는 발췌본 | 범위 일괄적용으로 발췌본 깊이를 나머지 공에 확장하는 경로를 마련. **다만 확장 규칙은 사람이 승인** (§8) |
| 무근 천공깊이가 H-PILE과 다름 | 천공종류별로 범위를 좁혀 적용 가능(`hole_type_code`). **단, 발췌본에서는 두 값이 동일합니다 → 8번 확인 요청** |

### 1.2 지층종류 (§7)

```
POST   /api/admin/sites/:id/ground-types    등록/수정 (배열 가능)
PATCH  /api/admin/ground-types/:id          수정
DELETE /api/admin/ground-types/:id          삭제 (사용 중이면 409 거부)
```

상태를 세 가지로 구분합니다.

| 상태 | 의미 |
|---|---|
| `CONFIRMED` | 계획수량이 확정된 지층 |
| `PROVISIONAL` | **수량산출서에 0으로 기재. 현장 여건에 따라 출현 가능** |
| `RETIRED` | 이 현장에서 더 이상 쓰지 않음 |

사용 중인 지층종류는 **DB 트리거가 삭제를 막습니다.** 대신 `RETIRED` 로 바꾸라고 안내합니다.

### 1.3 범위 일괄적용 (§10)

Master Prompt §10의 예시를 그대로 구현했습니다.

```
POST /api/admin/sites/:id/ground-assignments/preview
{
  "from": "A-031", "to": "A-065",
  "profile_name": "B구간 표준", "total_planned_depth": "21",
  "layers": [ {"ground_type_code":"G01","planned_length":"10"},
              {"ground_type_code":"G02","planned_length":"7"},
              {"ground_type_code":"G03","planned_length":"4"} ]
}
→ {
  "hole_count": 35, "first": "A-031", "last": "A-065",
  "layer_sum": 21, "total_planned_length": 735,
  "layer_totals": [ {"G01", per_hole:10, total:350}, ... ],
  "already_assigned": [], "issues": [], "can_save": true
}
```

`exclude` 로 제외번호를 지정할 수 있고(§19), `hole_type_code` 로 천공종류를 한정할 수 있습니다.

### 1.4 총연장 → 공당 환산 (§11)

> "반드시 사용자에게 계산 결과를 보여주고 확인을 받은 후 저장한다." (§11)

**환산 API는 계산만 하고 절대 저장하지 않습니다.** 응답에 `confirmation_required: true` 가 항상 포함됩니다.

실제 조서로 돌려본 결과입니다.

```
H-PILE 29공, 토사 총 438.06m
  → 438.06 ÷ 29 = 15.106 m/공
  → 재구성하면 438.074m  (잔여 -0.014m)

[WARN] 438.06m ÷ 29공 = 15.106m/공 으로 나누면 -0.014m 차이가 납니다.
       수량산출서가 공별로 다른 값을 가진다면 공별 입력을 사용하십시오.
```

**실제 수량산출서는 나누어떨어지지 않습니다.** 시스템이 이를 정확히 잡아내고
공별 입력을 쓰라고 안내합니다. §11 후단이 요구하는 그대로입니다.

### 1.5 공별 원본값 적용 (§11 후단)

> "수량산출서가 공별로 서로 다른 값을 가지고 있다면 원본 값을 그대로 적용한다."

같은 지층 조합끼리는 **하나의 지반조건을 공유**해 데이터가 불필요하게 늘지 않습니다.
실제 조서 58공은 27종 조합으로 정리됩니다.

### 1.6 지반조건 개정 (§38)

확정된 지반조건은 **수정하지 않습니다.** 개정하면 새 revision 이 생기고 이전 것은 `SUPERSEDED` 가 됩니다.

```
REV 0  토사 12m + 풍화암 8m           = 20m   ← 그대로 남아 조회 가능
REV 1  토사 12m + 풍화암 8m + 연암 3m = 23m   ← 현재 적용본
```

연결된 천공번호는 자동으로 새 revision 으로 옮겨지고, **각 공의 변경 전 값이 `hole_revision` 으로 보존**됩니다.

## 5. 계산 규칙

전부 결정론적입니다 (§46).

| 항목 | 규칙 |
|---|---|
| 범위 해석 | `sort_key BETWEEN fn_natural_sort_key(from) AND fn_natural_sort_key(to)` − 제외번호 |
| 지층합계 | `Σ planned_length`, 허용오차 1mm |
| 깊이구간 자동계산 | `from_depth = 직전 to_depth`, `to_depth = from + planned_length` (DEPTH_RANGE 모드) |
| 총연장 → 공당 | `round(total / hole_count, 3)` |
| 잔여 | `total − (per_hole × hole_count)`, 소수 3자리 |
| 구간 총량 | `per_hole × hole_count` |
| 조합 서명 | `"G01:14.600 + G02:2.400"` — 같은 조합은 지반조건 공유 |

**나누어떨어지지 않으면 반올림으로 덮지 않고 잔여를 그대로 보여줍니다.**
수량산출서 원본값을 시스템이 왜곡하지 않기 위해서입니다 (§11).

## 8. 사람이 직접 확인해야 할 사항

### ★ 1. 발췌본에서 H-PILE과 무근의 천공깊이가 **완전히 동일**합니다

"무근 천공깊이도 H-PILE 천공구간과 다르다"고 하셨는데, 업로드된 조서를 29쌍 전부 대조한 결과는 다릅니다.

```
        H-PILE                          무근
  1   토사 14.60  풍화암 2.40  계 17.00  |  1-1   토사 14.60  풍화암 2.40  계 17.00
  2   토사 14.60  풍화암 2.40  계 17.00  |  1-2   토사 14.60  풍화암 2.40  계 17.00
  4   토사 14.63  풍화암 2.37  계 17.00  |  1-4   토사 14.63  풍화암 2.37  계 17.00

  총심도가 다른 쌍: 0개 / 29쌍
  지층별 공당값이 다른 쌍: 0개 / 29쌍
```

세 가지 가능성이 있습니다. **어느 쪽인지 알려주십시오.**
- ① 발췌본이 단순화된 임시본이고 실제 설계에서는 달라진다
- ② 전체 638공 조서에서는 달라진다
- ③ 앞으로 다르게 설계할 예정이다

시스템은 이미 천공종류별로 다른 지반조건을 지원하므로 **코드 변경은 필요 없고 데이터만 넣으면 됩니다.**

### ★ 2. 29공 → 638.30공 확장 규칙

발췌본 29공의 깊이를 나머지 609공에 어떻게 펼칠지는 **제가 정하면 안 되는 영역**입니다 (§8).
아래 중 어느 것입니까?

- ① 29공 패턴을 반복 (1~29 → 30~58 → …)
- ② 구간별로 다른 값이 있고 발췌본은 1구간만 보여준 것
- ③ 전체 조서를 따로 주실 수 있음 ← **가장 정확합니다**

③이 가능하다면 PHASE 4에서 그대로 가져오면 됩니다.

### 3. 무근 `1-10, 2-10` 이 맞습니까?

조서의 `2.0`, `3.0` 을 앞 군의 10번째로 해석해 `1-10`, `2-10` 으로 넣었습니다.
`2-0` 이 맞다면 알려주십시오.

### 4. 계획 레미콘량 할증 2%가 전 현장 공통입니까?

`(3.14 × 0.6²)/4 × 연장 × 1.02` = **0.2826 ㎥/m**. PHASE 7에서 확정합니다.
