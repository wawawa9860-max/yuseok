## 0. 비전문가용 한 줄 요약

**엑셀 수량산출서를 올리면 시스템이 알아서 읽습니다.** 다만 **읽기만 합니다.**

Master Prompt가 못박은 원칙 때문입니다.

> "AI는 열 이름과 구조를 해석하는 보조 역할만 한다. 계약수량 변경을 자동 확정하지 않는다." (§12)

그래서 절차를 여섯 단계로 쪼갰습니다.

```
업로드 → 구조분석 → 매핑확인 → 미리보기 → 승인 → 반영
                     (사람)              (사람)
```

승인 버튼을 누르지 않으면 HOLE_MASTER는 **한 글자도 바뀌지 않습니다.**

그리고 이번 파서는 **업로드해주신 실제 조서로만** 검증했습니다. 합성 데이터를 쓰지 않았습니다.
결과: 58공 전부, 지층별 합계까지 원본과 소수점까지 일치합니다.

## 1. 이번에 구현한 기능

### 1.1 지시사항 반영

| 지시 | 반영 결과 |
|---|---|
| 발췌본은 단순화된 임시본, 앞으로 다르게 설계 | 원본값을 그대로 보존하고 확장은 별도 승인 절차로 분리 |
| **무근이 H-PILE보다 통상 짧다** | 자동검증 규칙 추가. 무근이 더 깊으면 `WARN`, 같으면 `INFO`로 확인 요청 |
| 29공 패턴 반복으로 진행 | 패턴 순환 확장 기능 구현. **단, 생성된 수량임을 항상 경고하고 승인을 요구** |

### 1.2 구조 자동 인식 — 좌표를 하드코딩하지 않는다

시트마다 레이아웃이 다르므로 **헤더 문구로 구조를 찾아냅니다.**

```
1. 'PILE NO.' 같은 천공번호 헤더를 모두 찾는다   → 블록 개수와 시작 열
2. '공당 / 소계' 가 늘어선 행을 찾는다           → 측정행
3. 그 윗행이 지층명 행이다                        → 지층 × 공당/소계 매트릭스
4. 번호가 비는 첫 줄에서 데이터가 끝난다          → 합계행과 분리
```

실제 조서에 돌린 결과입니다.

```
[A] H-PILE 구간 천공 (M)   헤더 R3 / 지층행 R4 / 측정행 R5 / 데이터 R6~R34 (29행)
    지층열: 토사(C2/C3) 풍화암(C4/C5) 연암(C6/C7) 경암(C8/C9)  합계열 C10  합계행 R36
[M] 무 근 천 공 (M)        헤더 R3 / 지층행 R4 / 측정행 R5 / 데이터 R6~R34 (29행)
    지층열: 토사(C14/C15) 풍화암(C16/C17) 연암(C18/C19) 경암(C20/C21)  합계열 C22
```

### 1.3 ★ 엑셀이 잃어버린 표기를 되살린다 (PHASE 3 위험 R9 해결)

PHASE 2에서 무근 2공이 조용히 사라졌던 원인이 이것입니다.

```
조서에 인쇄된 값:  1.1  1.2 … 1.9  2.0  2.1 …
엑셀이 저장한 값:  1.1  1.2 … 1.9   2   2.1 …     ← 2.0 이 정수 2 가 된다
셀 서식:          General                          ← 서식으로도 복원 불가
```

**같은 열의 다른 값들이 몇 자리 소수를 쓰는지 보고 복원합니다.**
1.1~1.9가 소수 1자리를 쓰므로 `2`도 `2.0`으로 되살립니다.

```ts
inferColumnDecimals(ws, col, from, to)  // → 1
restoreLabel(cell, 1)                   // 2 → '2.0'
```

이제 H-PILE `2`번과 무근 `2.0`이 **다른 번호로 구분**됩니다. 회귀 테스트로 고정했습니다.

### 1.4 산출근거 ↔ 천공조서 교차검증 (§14)

```
토사   산출근거 876.12m  =  조서 H-PILE 438.06 + 무근 438.06 = 876.12m   ✅
풍화암 산출근거 147.30m  =  조서 H-PILE  73.65 + 무근  73.65 = 147.30m   ✅
```

불일치는 **차단하지 않고 본사에 보고**합니다 (§43). 조서가 소수 2자리로 반올림돼 있어
허용오차 1cm를 둡니다.

### 1.5 발췌본 패턴 반복 확장

```
POST /expand-preview  { block_key:'A', numbering:{ mode:'RANGE', start:1, end:213 } }
→ 213공 생성, 29공 패턴 7.34주기
→ [WARN] 213공의 계획심도가 발췌본 29공을 반복해 생성되었습니다.
         실제 수량산출서 값이 아니므로 승인 전에 반드시 확인하십시오.
→ [WARN] 대상 213공은 발췌본 29공의 배수가 아닙니다. 마지막 주기는 10공만 사용됩니다.
```

**생성된 수량임을 항상 경고합니다.** §8이 금지한 "AI가 추측해서 계약수량을 확정"하는 일을
피하기 위해, 확장분은 `apply` 호출 시 `expansions` 를 명시해야만 반영됩니다.

### 1.6 무근 번호 변환

`1.1 → 1-1` 기계적 변환입니다. `2.0 → 2-0` 이 되는데, 이것이 의도한 표기인지
**추측하지 않고 경고를 띄웁니다.**

```
[WARN] DASH_ZERO_INDEX: 2.0 → 2-0 로 변환했습니다.
       조서의 '2.0' 은 앞 군의 마지막 번호를 뜻할 수도 있습니다. 확인하십시오.
```

블록별로 `RAW` / `DECIMAL_TO_DASH` 를 따로 고를 수 있어, H-PILE은 원문 그대로,
무근만 하이픈 형식으로 넣을 수 있습니다.

## 8. 사람이 직접 확인해야 할 사항

1. **무근 `2.0` → `2-0` 표기가 맞습니까?**
   조서의 소수 연번을 기계적으로 하이픈으로 바꾼 결과입니다.
   `1-10`(앞 군의 10번째)이 의도라면 알려주십시오. 매핑 옵션만 바꾸면 됩니다.

2. **패턴 반복 확장 시 번호 체계.**
   H-PILE을 213공으로 늘리면 `1 … 213`이 됩니다. 실제 도면 번호가 다르다면
   `LIST` 모드로 도면 번호를 그대로 붙여넣는 편이 정확합니다.

3. **확장 실행 시점.**
   현재 발췌본 58공만 반영해 둔 상태입니다. 638.30공으로 확장할지, 아니면
   **전체 조서를 받은 뒤에 할지** 정해 주십시오. 후자를 권합니다 —
   생성된 수량은 어디까지나 임시값이기 때문입니다.

4. **계획 레미콘 할증 2%가 전 현장 공통입니까?** (PHASE 7에서 확정)

5. **작업도면 PDF** — PHASE 5의 필수 입력물입니다.
