## 0. 비전문가용 한 줄 요약

**현장에서 생긴 일을 한 장으로 남깁니다.**

§31 이 정한 원칙 그대로입니다.

> "별도의 복잡한 안전/품질/민원 ERP를 만들지 않는다.
>  RF CIP 업무와 직접 관계되는 SPECIAL_EVENT 하나로 통합한다."

현장관리자가 하는 일은 세 가지뿐입니다.
**유형을 하나 고르고, 필요하면 천공번호를 누르고, 사진을 찍는다.**
실제 브라우저 기준 **6터치 + 내용 한 줄**로 사진·번호연결·검토표시까지 끝납니다.

가장 중요한 설계는 **다시 묻지 않는 것**입니다 (§1-2).
레미콘 지연, 장비 대기, 계획심도 미달, 지반 특이사항은 **일일입력이 이미 받았습니다.**
특이사항 화면은 그것들을 모아서 보여줄 뿐, 같은 내용을 또 적게 하지 않습니다.
화면에도 그대로 적어 두었습니다 — *"이미 입력하신 내용입니다. 다시 적을 필요 없습니다."*

## 1. 이번에 구현한 기능

### 1.1 §31 특이사항 등록

- **유형 17종** — 레미콘 지연 / 장비대기 / 장비고장 / 작업부지 미조성 / 검측지연 /
  지반조건 변화 / 지하수 / 슬라임 / H-BEAM / 가이드월 / 우천 / 유류 / 추가천공 /
  추가작업 / 작업구간 변경 / 원도급 지시 / 기타.
  서버가 내려주는 선택지라 코드 수정 없이 바꿀 수 있습니다.
- **사진·음성메모 연결** — 사진(jpg/png/heic/webp/pdf)과 음성(m4a/mp3/aac/wav 등)을
  붙일 수 있습니다. 원가가 아니므로 현장·본사가 함께 봅니다.
- **오프라인 대응** — 통신이 끊긴 채 등록하면 큐에 쌓이고, 사진은 사건이 먼저
  전송된 뒤 그 사건 번호로 따라 붙습니다.

### 1.2 §32 천공번호 연결 + 사건번호

```
EV-2027-0001
  유형      지반조건 변화
  관련 천공  E-003, E-004
  증빙      사진 1장, 음성메모 1건
  변경/정산 검토: YES
```

- 번호는 **현장·연도별 순번**(EV-YYYY-NNNN)으로 자동 채번됩니다.
  동시에 등록해도 겹치지 않습니다 (advisory lock, 테스트로 확인).
- 도면에 없는 천공번호를 걸면 **조용히 버리지 않고** `unknown_holes` 로 알려줍니다 (§8).
- **`변경/정산 검토` 표시** — §32 의 "변경/정산 검토: YES" 입니다. 이 표시가 있는
  사건이 열려 있으면 §43 본사 검증에 `EVENT_NEEDS_REVIEW` 경고가 뜨고,
  본사가 검토를 마치고 **종결**하면 사라집니다. 종결은 본사만 합니다.

### 1.3 §31 통합 조회 — 재입력 금지 (§1-2)

`GET /api/events/sites/:id/events` 하나가 전부 돌려줍니다.

| 구분 | 출처 |
|---|---|
| 등록된 사건 (사진·검토표시 포함) | `special_event` |
| 레미콘 지연 | 일일입력 §23 |
| 장비 대기·반일 + 사유 | 장비가동일보 §26 |
| 계획심도 미달 + 사유 | 일일입력 §16 |
| 지반 특이사항 | 일일입력 §15 |

### 1.4 §33 작업일보 합류

PHASE 9 에서 자리만 만들어 둔 작업일보의 특이사항 칸에 등록 사건이 합류했습니다.
지반 특이사항과 사건이 한 칸에 나오고, 사건은 번호(EV-…)와 검토표시가 함께 나옵니다.

## 8. 사람이 직접 확인해야 할 사항

1. **유형 17종이 실제 현장 용어와 맞습니까?** §31 예시 그대로 넣었습니다.
