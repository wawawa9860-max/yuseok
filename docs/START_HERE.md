# 여기서 시작 — 이 시스템이 무엇이고, 뭘 누르면 되는지

> "전체적으로 어떤 파일을 들어가서 어떻게 셋팅하며 운영하는지 이해가 잘 가지 않는다"
> 는 질문에 대한 답입니다. **결론: 파일을 들어갈 일이 없습니다.**

## 이 시스템은 무엇인가

RF CIP 현장의 하루를 이렇게 만듭니다:

```
현장관리자(휴대폰): 퇴근 전 1~3분 입력 → [카카오톡 공유] 버튼
본사(PC/휴대폰):   대시보드에서 이상 있는 현장만 클릭해 확인
계약상대방:        원가 없는 작업현황 링크만 받아봄
```

작업일보·천공일지·공정률·기성·투입원가는 **이미 입력한 값으로 자동으로** 만들어집니다.
같은 것을 두 번 적는 일이 없도록 만들어져 있습니다.

## 셋팅은 언제 무엇을 하나 — 전체 그림

전부 합쳐 **3가지 층**이 있고, 파일을 만지는 층은 없습니다.

### ① 서버 만들기 — 처음 딱 1회, 약 15분
클라우드(Railway)에서 클릭 몇 번으로 서버·DB·**https 주소**가 만들어집니다.
환경값 4개(비밀번호 등)를 웹 화면의 빈칸에 입력하는 것이 전부입니다.
→ **docs/CLOUD_DEPLOY_GUIDE.md** 순서대로.

서버가 켜지는 순간 DB 구조 생성과 본사 계정(admin) 생성까지 **자동으로** 끝납니다.

### ② 현장 최초설정 — 현장마다 1회, 본사가 웹에서
운영 주소로 로그인 → 대시보드. 화면이 안내하는 순서대로:

```
계정 관리에서 현장관리자 계정 만들기
→ 현장 등록
→ 사전 업로드 5종: 계약내역서 · 천공조서 · 수량산출서 · 공내역서 · 작업도면
→ 천공번호 · 지층 · 계획심도 · 단가연결 · 기본 인원/장비
```

여기가 가장 손이 가는 단계입니다. **최초설정을 상세히 해 두는 대신,
매일 입력이 1~3분으로 줄어듭니다** (이 시스템의 기본 원칙).
→ 자세한 순서는 **docs/PILOT_GUIDE.md** 5단계.

### ③ 매일 운영 — 아무도 셋팅하지 않음
현장관리자는 홈 화면 아이콘을 눌러 입력하고 공유 버튼을 누릅니다.
본사는 대시보드를 봅니다. 끝.

## 자주 하는 오해

- **".env 파일을 만들어야 하나요?"** — 클라우드 배포에서는 아니요.
  Railway 화면의 Variables 빈칸에 4개 값을 넣는 것으로 대체됩니다.
  (.env 는 사무실 PC 에 직접 설치하는 경우에만 씁니다.)
- **"계정은 어디서 만드나요?"** — 웹에서. 본사 대시보드 → [계정 관리].
  psql·시드파일·개발자가 필요 없습니다.
- **"프로그램이 업데이트되면?"** — GitHub 에 새 코드가 올라오면 Railway 가
  자동으로 다시 배포하고, DB 변경도 서버가 켜지면서 자동 적용됩니다.
- **"서버가 안 켜져요"** — Railway 의 View Logs 를 열면 서버가
  **한국어로 무엇이 빠졌는지** 말해 줍니다. 조용히 죽지 않습니다.
