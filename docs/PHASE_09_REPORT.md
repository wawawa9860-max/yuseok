## 1. 이번에 구현한 기능

### 1.1 §33 작업일보 자동생성

§33 이 요구한 항목을 전부 담았습니다.

| §33 항목 | 어디서 오는가 |
|---|---|
| 일자 · 현장 | SITE |
| 작업구간 | 금일 천공번호들의 `section` |
| 작업내용 | 메모가 있으면 메모, 없으면 `RF CIP 천공 N공` |
| 금일 천공번호 | 일일입력. **도면 순서(`sort_key`)로 정렬** |
| 금일 공수 | 천공 공수 (몇 공) |
| 누계 공수 | 완료 누계 / 전체 |
| 금일 천공연장 | **실제심도 기준.** 예외가 있으면 계획이 아니라 실제를 쓴다 |
| 지층별 계획 천공연장 | 지반조건 × 금일 공수 |
| 레미콘 | 반입량 · 지연시간 · 사유 |
| 인원 | **출력일보** (인원 × 공수 = 투입공수, 사유 포함) |
| 장비 | **장비가동일보** (가동일수, 미가동 사유 포함) |
| 특이사항 | 지반 특이사항 + 관련 천공번호 (§32) |
| 익일계획 | 적은 값, 없으면 다음 미시공 번호 제안 |

`금일 공수` 라는 말이 두 가지 뜻으로 쓰여서 이름을 나눴습니다.

```
hole_count           천공 공수 — 몇 공을 뚫었나  (§33 의 '금일 공수')
today_man_days       투입 공수 — 사람이 며칠치 나왔나 (§25 출력일보)
```

일보에는 **둘 다** 들어갑니다.

### 1.2 §34 천공일지 자동생성 — **천공조서와 같은 칸**

> 사용자 확인 (2026-08-27): "천공조서와 거의 동일하다고 보면 된다."

그래서 수량산출서의 **천공조서와 같은 칸 구성**으로 냅니다.

```
천공조서 :  PILE NO │ 토사 공당 │ 풍화암 공당 │ 연암 │ 경암 │ 합계
천공일지 :  같은 칸  + 실제심도 · 시공일 · 상태
```

**지층 칸은 현장이 정한 지층으로 만듭니다.** 시스템이 '토사/풍화암/연암/경암' 을 박지 않습니다 (§7).
계획수량 0 인 미확정 지층(`PROVISIONAL`)도 **칸은 그대로 둡니다.** 조서 원본이 그렇습니다.

**지층 합계 ≠ 계획심도** 이면 그 사실을 일지에 그대로 드러냅니다.
조서 자체가 어긋나 있을 수 있고, 그것을 숨기면 사람이 못 찾습니다.

목록도 조서 형태로 냅니다.

| API | 내용 |
|---|---|
| `GET /api/reports/sites/:id/drilling-register` | 조서 전체 + 지층 칸 목록 + **합계행** + 어긋난 공 |

합계행은 조서 원본의 마지막 줄과 같습니다 — 천공종류별 공수·지층별 소계·합계, 그리고 실적.

### 1.2a 천공일지 상세 항목

§34 예시 그대로입니다.

```
A-003
  종류        H-PILE 구간
  계획심도    20 m
  실제심도    23.4 m
  계획 대비   +3.4 m      ← 차이를 숨기지 않는다
  시공일      2026-08-27
  계획 지층   토사 14m / 풍화암 6m
  레미콘      30 m³ 연결
  특이사항    지하수
  이력        revision 목록 (§38)
```

**미시공 천공도 일지가 나옵니다.** 계획만 있는 상태로 보여줍니다.
**천공번호 형식을 강제하지 않습니다.** `1-1` 같은 무근 번호도 원문 그대로 찾습니다.

### 1.3 §35 작업도면 = 천공일지 = 수량산출 실적

§35 는 이 셋이 **항상 일치**해야 한다고 못박습니다.
같은 테이블을 두 번 세면 당연히 같으므로, **서로 다른 경로**로 센 값을 맞춰 봅니다.

| 출처 | 무엇을 세나 |
|---|---|
| 작업도면 | 도면 진행상태 뷰에서 '완료' 로 보이는 것 |
| 천공일지 | 일일작업에 실제로 찍힌 것 |
| 수량산출실적 | HOLE_MASTER 의 상태 |

공수와 연장이 모두 같아야 하고, 어긋나면 **ERROR** 로 잡습니다.
`GET /api/reports/sites/:id/progress-consistency` 로 언제든 확인할 수 있고
§43 자동검증에도 들어갑니다.

## 5. 계산 규칙

일보가 새로 계산하는 값은 없습니다. 이미 저장된 값을 모읍니다.
다만 두 가지는 **어느 값을 쓰는지** 가 중요합니다.

```
금일 천공연장 = Σ COALESCE(그날 실제심도, 계획심도)
                 ↑ 예외를 적은 공은 실제, 안 적은 공은 계획

누계 천공연장 = Σ COALESCE(HOLE 의 실제심도, 계획심도)   (완료분만)

지층별 계획연장 = Σ (지반조건의 지층별 길이)             (금일 공수 전체)
```

익일계획 제안은 **미시공 천공을 `sort_key` 순서로 최대 10개**입니다.
문자열 정렬이 아니라 도면 순서입니다 (§10).
**제안일 뿐 확정이 아닙니다** (§11).

## 9. 발견된 위험

### 9.1 ★ 일일입력이 통째로 깨지는 버그 (고침)

**증상.** `[아니오] 계획심도와 다름` 을 누르고 **한 공만** 실제심도를 적으면
저장이 400 으로 실패했습니다. 메시지도 DB 제약조건 이름이 그대로 나왔습니다.

**원인.** 날짜 단위 `[아니오]` 를 **모든 공이 계획과 다르다** 는 뜻으로 저장했습니다.
안 적은 공은 '다름 + 실제심도 없음' 이 되어 제약조건에 걸렸습니다.
화면 문구는 `다른 공만 적으십시오. 비워두면 계획심도를 씁니다.` 인데
서버가 그 문구대로 동작하지 않았습니다.

**이게 왜 위험한가.** `[아니오]` 를 누르고 **일부만 적는 것이 정상적인 사용법**입니다.
5공 중 1공만 깊게 뚫는 날이 흔합니다. 즉 **가장 흔한 예외 입력이 통째로 막혀 있었습니다.**

**왜 못 잡았나.** PHASE 6·7 테스트는 예외를 적을 때 **모든 공에 다 적었습니다.**
브라우저 확인도 매번 `[예]` 만 눌렀습니다. 이번에 PHASE 9 테스트를 만들면서
"1공만 다른 날" 을 처음 재현해 걸렸습니다.

**고침.** 공 단위로 판단합니다. `적은 공만 예외, 나머지는 계획심도.`
PHASE 6 에 회귀 테스트 2개를 남겼습니다.

### 9.2 ★ 통신이 끊긴 곳에서 앱이 아예 안 열렸다 (고침)

**증상 1.** 서비스워커 캐시 목록에 `pick.js` / `queue.js` 가 빠져 있었습니다.
`app.js` 가 이 둘을 `import` 하므로, 통신이 끊긴 채로 앱을 새로 열면
모듈을 못 받아 **화면이 통째로 안 떴습니다.**

**증상 2.** 쉘이 떠도 `/api/auth/me` 가 실패해 **로그인 화면으로 튕겼습니다.**
저장된 토큰과 받아둔 자료가 있어도 못 썼습니다.

**증상 3.** 입력화면을 온라인에서 한 번도 안 열었으면 천공번호 목록 캐시가 없어서
`[오늘 작업 입력]` 을 눌러도 **아무 일도 일어나지 않았습니다.**

**이게 왜 위험한가.** PHASE 7 의 오프라인 큐는 "앱이 이미 열려 있는 상태" 만 지켰습니다.
현장관리자는 보통 **사무실에서 앱을 닫고, 현장에 들어가서 다시 엽니다.**
그 경로가 막혀 있었습니다.

**고침.**
- 캐시 목록에 모듈과 아이콘을 추가하고 캐시 이름을 `v2` 로 올렸습니다.
- 마지막으로 확인된 내 정보를 기기에 남겨 통신이 안 되면 그것으로 엽니다.
- **메인 화면에 들어오면 입력화면 자료를 미리 받아 둡니다.**
  통신 되는 곳에서 앱을 한 번 열어두면 현장에서 그대로 입력할 수 있습니다.
- 그래도 자료가 없으면 **왜 안 되는지 말해 줍니다.** 버튼을 눌렀는데 아무 일도
  안 일어나는 것이 제일 나쁩니다.

**검증.** 실제 브라우저로 온라인 사용 → 앱 종료 → 비행기모드 콜드스타트:
앱이 열리고, 천공번호 50개가 보이고, 입력이 저장 대기 1건으로 쌓입니다.

### 9.3 홈 화면 아이콘이 없었다 (고침)

`manifest.webmanifest` 의 `icons` 가 비어 있어 **홈 화면에 추가하면 아이콘이 없었습니다.**
시험사용에서 현장관리자가 앱을 못 찾습니다. 아이콘 3종(192/512/180)을 만들어 넣었습니다.
아이폰은 manifest 아이콘을 안 쓰므로 `apple-touch-icon` 도 따로 넣었습니다.

### 9.4 남아 있는 주의점

- **특이사항은 아직 '지반 특이사항' 뿐입니다.** §31 SPECIAL_EVENT 17종과
  사진·음성메모 연결은 PHASE 11 입니다. 일보에 자리는 만들어 두었습니다.
- **작업일보를 저장하지 않습니다.** 매번 원본에서 다시 만듭니다.
  원본이 바뀌면 일보도 바뀝니다. 이것이 §35(항상 일치)에는 맞지만,
  **제출한 일보를 그 시점 그대로 남겨야 한다면** 확정 스냅샷이 필요합니다.
  §38 revision 구조가 이미 있으므로 필요하시면 붙이겠습니다. **확인 부탁드립니다.**
